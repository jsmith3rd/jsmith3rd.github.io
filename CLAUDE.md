## Commands

```bash
npm run dev       # Dev server with HMR
npm run build     # Type-check (vue-tsc) then production build → dist/
npm run preview   # Preview production build locally
npm run deploy    # Push dist/ to GitHub Pages via gh-pages
```

`npm run build` runs `vue-tsc -b` first — TypeScript errors block the build entirely. Node 24 is required.

## Architecture

Single-page portfolio site: Vue 3 + TypeScript + Vite, no routing, no state management, no UI framework.

```
src/
  main.ts             # createApp(App) → installAnalytics(app) → mount('#app')
  App.vue             # Root: scroll tracking, section observer, QR/map modal state
  style.css           # All styles (global CSS variables + component styles, no scoped styles except SocialLinks.vue)
  config/site.ts      # Single source of truth for all portfolio content
  lib/analytics.ts    # Consent-aware Google Analytics wrapper (vue-gtag)
  components/         # Page sections + UI primitives
plugins/
  favicon-plugin.ts   # Build-only: rasterizes public/logo-square.svg → dist/ favicons (reference pattern for all plugins)
  cname-plugin.ts     # Build-only: copies root CNAME → dist/CNAME
```

**Content changes go in `src/config/site.ts` only** — no database, no CMS. All text, links, case studies, timeline, and vCard data live there.

**App.vue** owns all cross-section concerns: active nav section tracking (scroll + IntersectionObserver), scroll depth analytics milestones (25/50/75/100%), QR overlay and map modal state, and cookie consent hookup.

**Analytics** (`src/lib/analytics.ts`) is consent-gated: starts denied/opted-out, only loads the gtag script after `ConsentBanner.vue` fires `setAnalyticsConsent(true)`. Requires `VITE_GTAG_ID` env var — silently no-ops if absent (safe for dev).

## Key Conventions

- **`<script setup lang="ts">`** throughout — no Options API, no `export default`
- **`defineProps<T>()`** with TypeScript generics — no runtime prop schemas
- **Strict TypeScript**: `noUnusedLocals`, `noUnusedParameters`, `erasableSyntaxOnly` — unused imports/vars are build errors
- **CSS**: kebab-case classes, predominantly in `src/style.css` using CSS custom properties; `SocialLinks.vue` is the one exception with scoped styles
- **Vite plugins**: use `configResolved()` to derive paths from config, guard all output with `isBuild` flag, run work in `closeBundle()`; `plugins/favicon-plugin.ts` is the reference pattern

## Keeping Socials in Sync

`README.md` duplicates social links in two places — the badge row at the top and the "Get in Touch" list. When `socialLinks` in `src/config/site.ts` changes, update both locations in `README.md`:

- **Badge row**: `[![Label](badge-url)](href)` — match the `badge` object params from `site.ts`
- **"Get in Touch" list**: plain markdown links with updated handles/URLs

## Deployment

Push to `main` → GitHub Actions (`.github/workflows/deploy.yml`) runs type-check → build → deploys `dist/` to the `gh-pages` branch. `VITE_GTAG_ID` is injected as a CI secret. The workflow copies `dist/index.html` → `dist/404.html` for SPA routing fallback.

## Non-Obvious Details

- **Favicons are build-only** — the favicon plugin does not run in dev; `public/logo-square.svg` is the source
- **Social badge images are runtime URLs** — `SocialLinks.vue` constructs `custom-icon-badges.demolab.com` URLs dynamically; no static badge images are committed
- **`dist/CNAME`** is generated by `cname-plugin` from the root `CNAME` file — do not add a `public/CNAME`
- **Cookie consent** uses `localStorage` (not cookies), key `jsmith3rd-cookie-consent`, expires after 182 days; `LEGACY_STORAGE_KEY` is cleared on mount to migrate old visitors
