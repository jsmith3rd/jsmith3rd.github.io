# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev       # Dev server with HMR
npm run build     # Type-check (vue-tsc) then production build → dist/
npm run preview   # Preview production build locally
npm run deploy    # Push dist/ to GitHub Pages via gh-pages
```

`npm run build` runs `vue-tsc -b` first — TypeScript errors block the build entirely. Node 24 is required.

## Architecture

Single-page portfolio site: Vue 3 + TypeScript + Vite, no routing, no state management, no UI framework.

```
src/
  main.ts             # createApp(App) → installAnalytics(app) → mount('#app')
  App.vue             # Root: scroll tracking, section observer, QR overlay state
  style.css           # Global CSS variables, resets, and shared classes; most components layer scoped styles on top
  config/site.ts      # Single source of truth for all portfolio content
  lib/analytics.ts    # Consent-aware Google Analytics wrapper (vue-gtag)
  components/         # Page sections (NavBar, HeroSection, HighlightsBand, WorkSection,
                       #   AboutSection, ContactSection, FooterBar) + primitives
                       #   (ConsentBanner, QrOverlay, SocialLinks, VCardDownload)
plugins/
  favicon-plugin.ts       # Build-only: rasterizes public/logo-circle.svg → dist/ favicons (reference pattern for all plugins)
  cname-plugin.ts         # Build-only: copies root CNAME → dist/CNAME
  article-dates-plugin.ts # Injects __ARTICLE_PUBLISHED_TIME__/__ARTICLE_MODIFIED_TIME__ into index.html's OG meta tags at build time
```

**Content changes go in `src/config/site.ts` only** — no database, no CMS. All text, links, case studies, timeline, and vCard data live there.

**App.vue** owns all cross-section concerns: active nav section tracking (scroll + IntersectionObserver), scroll depth analytics milestones (25/50/75/100%), QR overlay state, and cookie consent hookup.

**Analytics** (`src/lib/analytics.ts`) is consent-gated: starts denied/opted-out, only loads the gtag script after `ConsentBanner.vue` fires `setAnalyticsConsent(true)`. Requires `VITE_GTAG_ID` env var — silently no-ops if absent (safe for dev).

## Key Conventions

- **`<script setup lang="ts">`** throughout — no Options API, no `export default`
- **`defineProps<T>()`** with TypeScript generics — no runtime prop schemas
- **Strict TypeScript**: `noUnusedLocals`, `noUnusedParameters`, `erasableSyntaxOnly` — unused imports/vars are build errors
- **CSS**: kebab-case classes. `src/style.css` holds global variables, resets, and classes shared across components; nearly every component additionally has its own `<style scoped>` block for layout/styling specific to it. `ConsentBanner.vue` is the exception — it has no scoped styles and instead imports `vanilla-cookieconsent/dist/cookieconsent.css` directly.
- **Vite plugins**: use `configResolved()` to derive paths from config, guard all output with `isBuild` flag, run work in `closeBundle()`; `plugins/favicon-plugin.ts` is the reference pattern

## Keeping Socials in Sync

`README.md` duplicates social links in two places — the badge row at the top and the "Get in Touch" list. When `socialLinks` in `src/config/site.ts` changes, update both locations in `README.md`:

- **Badge row**: `[![Label](badge-url)](href)` — match the `badge` object params from `site.ts`
- **"Get in Touch" list**: plain markdown links with updated handles/URLs

## Deployment

Push to `main` → GitHub Actions (`.github/workflows/deploy.yml`) runs type-check → build → uploads `dist/` as a Pages artifact and deploys it via `actions/deploy-pages` (the official GitHub Pages flow — **not** a push to a `gh-pages` branch). `VITE_GTAG_ID` is injected as a CI secret. The workflow copies `dist/index.html` → `dist/404.html` for SPA routing fallback.

> `npm run deploy` (`gh-pages -d dist`) is a leftover manual-deploy script: the `gh-pages` package is not currently an installed dependency, so this script will fail as-is. It is not used by CI; deployment happens automatically on push to `main`.

## Non-Obvious Details

- **Favicons are build-only** — the favicon plugin does not run in dev; `public/logo-circle.svg` is the source
- **Social badge images are runtime URLs** — `SocialLinks.vue` constructs `custom-icon-badges.demolab.com` URLs dynamically; no static badge images are committed
- **`dist/CNAME`** is generated by `cname-plugin` from the root `CNAME` file — do not add a `public/CNAME`
- **Article dates** (`article:published_time`/`article:modified_time` OG meta tags in `index.html`) are stamped by `article-dates-plugin`: published time is a hardcoded constant in the plugin source, modified time is set to the current timestamp on every build
- **Cookie consent** uses `localStorage` (not cookies), key `jsmith3rd-cookie-consent`, expires after 182 days; `LEGACY_STORAGE_KEY` is cleared on mount to migrate old visitors
