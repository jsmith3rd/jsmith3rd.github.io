# Agent Instructions

Personal portfolio site — a single-page card built with Vue 3 + Vite + TypeScript, deployed to GitHub Pages at `jsmith3rd.dev`.

## Commands

```bash
npm run dev       # Dev server with HMR
npm run build     # Type-check (vue-tsc) then production build → dist/
npm run preview   # Preview production build locally
npm run deploy    # Push dist/ to GitHub Pages via gh-pages
```

> `npm run build` runs `vue-tsc -b` first — TypeScript errors block the build entirely.

## Architecture

Single-page component tree; no routing, no state management, no UI framework.

```
src/
  main.ts             # createApp(App) → installAnalytics(app) → mount('#app')
  App.vue             # Root — active nav section tracking, scroll depth analytics, QR overlay state
  style.css           # Global CSS variables, resets, and shared classes; most components layer scoped styles on top
  config/site.ts      # Single source of truth — edit this to update portfolio content
  lib/analytics.ts    # Consent-aware Google Analytics wrapper (vue-gtag)
  components/
    NavBar.vue, HeroSection.vue, HighlightsBand.vue, WorkSection.vue,
    AboutSection.vue, ContactSection.vue, FooterBar.vue   # page sections
    ConsentBanner.vue, QrOverlay.vue, SocialLinks.vue, VCardDownload.vue  # primitives
plugins/
  favicon-plugin.ts       # Build-time: rasterizes public/logo-circle.svg → dist/ favicons
  cname-plugin.ts         # Build-time: copies root CNAME → dist/CNAME
  article-dates-plugin.ts # Build-time: injects article published/modified time into index.html OG tags
```

## Key Conventions

- **`<script setup lang="ts">`** throughout — no Options API, no `export default`
- **`defineProps<T>()`** with TypeScript generics — no runtime prop schemas
- **Strict TypeScript**: `noUnusedLocals`, `noUnusedParameters`, `erasableSyntaxOnly` — unused imports/vars are errors
- **CSS**: kebab-case classes. `src/style.css` holds global variables, resets, and shared classes; nearly every component also has its own `<style scoped>` block. `ConsentBanner.vue` is the exception — no scoped styles, it imports `vanilla-cookieconsent`'s CSS directly.
- **Vite plugins**: `configResolved()` to derive paths from config, guard with `isBuild` flag, run in `closeBundle()`; see [plugins/favicon-plugin.ts](plugins/favicon-plugin.ts) as the reference pattern

## Content Changes

All portfolio content (name, tagline, social links, badge styles) is in [`src/config/site.ts`](src/config/site.ts). This is the only file that needs editing for content updates — no database, no CMS.

### Keeping socials in sync

[`README.md`](README.md) duplicates the social links in two places — the badge row at the top and the "Get in Touch" list. Whenever `socialLinks` in `src/config/site.ts` is added, removed, or changed, update both locations in `README.md` to match:

- **Badge row** (top of file): `[![Label](badge-url)](href)` — construct the badge URL using the same parameters as the `badge` object in `site.ts`
- **"Get in Touch" list**: plain markdown links matching the updated handles/URLs

## Deployment

Push to `main` → GitHub Actions ([.github/workflows/deploy.yml](.github/workflows/deploy.yml)) runs type-check → build → uploads `dist/` as a Pages artifact and deploys it via `actions/deploy-pages` (the official GitHub Pages flow, not a push to a `gh-pages` branch). The workflow also copies `dist/index.html` → `dist/404.html` for SPA routing fallback.

> `npm run deploy` (`gh-pages -d dist`) is a leftover manual-deploy script — the `gh-pages` package isn't currently an installed dependency, so it will fail as-is and isn't used by CI.

## Non-Obvious Details

- **Favicons are build-only** — the favicon plugin does not run in dev; `public/logo-circle.svg` is the source
- **Social badges are runtime URLs** — `SocialLinks.vue` constructs `custom-icon-badges.demolab.com` URLs dynamically; no static badge images are committed
- **`dist/CNAME`** is generated by `cname-plugin` from the root `CNAME` file — do not add a `public/CNAME`
- **Article dates** in `index.html`'s OG meta tags are stamped by `article-dates-plugin`: published time is a hardcoded constant, modified time is set to the current timestamp on every build
- **Node 24** is required; the CI workflow enforces this
